# cloudtrail-attack-gliclass

## 목적

GLiClass의 **제로샷 성능을 유지하면서**, **퓨샷 파인튜닝**으로 CloudTrail 같은 로그의 **공격 분류 성능을 끌어올리는 것**이 목적이다.

1. 퓨샷 파인튜닝으로 CloudTrail 공격 분류 성능을 높인다.
2. 기존 모델의 제로샷·퓨샷 능력을 유지한다.
3. 비슷한 로그 형식의 다른 데이터에서도 제로샷·퓨샷 성능을 검증한다.

### 목표 간 대비

| | 새 도메인 성능 (목표 1) | 기존 능력 유지 (목표 2) | 일반화 (목표 3) |
|---|---|---|---|
| 무엇을 보나 | CloudTrail 공격 분류 성능 향상 | 기존 벤치마크의 제로샷 성능 하락 여부 | 학습에 안 쓴 유사 로그에서의 성능 |
| 위험 | 과적합 (k가 작을 때) | 파인튜닝으로 기존 능력을 잊어버림 | CloudTrail 형식에만 맞춰짐 |
| 비교 기준 | 파인튜닝 전 제로샷 vs 파인튜닝 후 | 파인튜닝 전 vs 후 (기존 데이터) | 제로샷 vs 퓨샷 (유사 로그) |

목표 1과 목표 2는 서로 당기는 관계다. 새 도메인에 많이 맞출수록 기존 능력이 떨어질 수 있어서, 둘 사이의 균형을 찾는 것이 핵심이다.

## 가설

| 가설 | 내용 | 검증 방법 | 상태 |
|---|---|---|---|
| H1 | 소량(k-shot)의 CloudTrail 데이터로 파인튜닝하면 공격 분류 성능이 제로샷보다 오른다. | k별 성능을 파인튜닝 전 제로샷과 비교 | 미검증 |
| H2 | 기존 GLiClass 학습 데이터를 섞어서 학습하면 제로샷 성능을 유지할 수 있다. | 기존 데이터 섞음 vs 안 섞음, 기존 벤치마크 성능 비교 | **가설이 맞는지 조사 필요** |
| H3 | CloudTrail로 학습한 능력이 비슷한 형식의 다른 로그에도 옮겨간다. | 유사 로그 데이터에서 제로샷·퓨샷 성능 측정 | 미검증 |

## 파인튜닝 데이터셋

두 종류의 데이터를 쓴다. 역할이 서로 다르다.

| | ① 기존 GLiClass 학습 데이터 | ② CloudTrail 윈도우 데이터 |
|---|---|---|
| 역할 | 제로샷 성능 유지 (H2) | 공격 분류 성능 향상 (H1) |
| 출처 | GLiClass 원 학습 데이터셋 | CloudTrail 윈도우 분할 논문의 데이터셋을 그대로 사용 |
| 양 | 기존 능력을 지킬 만큼 | k-shot (소량) |
| 확인할 것 | 데이터 공개 여부, 섞는 비율 | k, 실제·가상 비율, 라벨 체계 |

### ① 기존 GLiClass 학습 데이터 (제로샷 유지)

- [ ] 기존 데이터를 섞으면 제로샷 성능이 유지된다는 **가설이 맞는지 조사**
- [ ] 기존 기능을 그대로 남겨둔 채 파인튜닝하는 **GLiClass 파인튜닝 방법과 학습 알고리즘 조사**
- 구현: numpy, pytorch, pandas

조사할 파인튜닝 방식 후보 (서로 대비):

| 방식 | 기존 능력 유지 | 새 도메인 적응 | 비고 |
|---|---|---|---|
| 전체 파인튜닝 | 약함 (잊어버리기 쉬움) | 강함 | 기준선 |
| 기존 데이터 섞어 학습 (replay) | 강함 | 보통 | 기존 데이터 확보 필요 |
| 일부 파라미터만 학습 (LoRA 등 PEFT) | 강함 | 보통 | 원 모델 가중치 보존 |

위 표는 조사 전의 예상이며, 조사 결과에 따라 고친다.

### ② CloudTrail 윈도우 데이터 (공격 분류)

CloudTrail 윈도우 분할 논문의 데이터셋을 그대로 가져온다. 데이터는 두 종류다.

| | 실험 생성 데이터 (가상) | 실제 데이터 |
|---|---|---|
| 특징 | 공격 시나리오를 실행해 만든 로그, 라벨이 정확함 | 실제 환경 로그, 정상 행위가 다양함 |
| 한계 | 실제 분포와 다를 수 있음 | 공격 라벨이 적거나 불확실함 |

- **퓨샷 k:** 1, 3, 5, 8, 16 (최대 16)
- **데이터 구성:**
  - [ ] 필요한 이벤트를 고르고 시간순으로 정렬
  - [ ] 실제 데이터와 가상 데이터의 비율 정하기
- **분류 과제:**

| | 이진 분류 | MITRE ATT&CK 분류 |
|---|---|---|
| 라벨 | 정상 / 공격 | 전술(tactic), 기법(technique) |
| 난이도 | 낮음 | 높음 (라벨 수가 많고 멀티라벨 가능) |
| 윈도우 라벨링 | 방식 1·2 모두 적용 가능 | 기법 단위 라벨이 필요 (`notebooks/window.ipynb` 참고) |

## 폴더 구조

```
./
├── README.md              # 목적, 설치, 실행 방법, 데이터 받는 법
├── requirements.txt       # gliclass, transformers, torch 버전 고정
├── labels/
│   ├── attack_labels_v19.csv
│   ├── stratus_mapping.csv
│   └── build_labels.py
├── src/
│   ├── preprocess.py      # 서비스 이벤트 제외, 누출 제거, 반복 압축
│   ├── windows.py         # 세션 분할, 슬라이딩 윈도우
│   ├── features.py        # 행위·파생 특징 → 텍스트
│   ├── hier_classify.py   # top-down / bottom-up
│   ├── evaluate.py
│   └── finetune.py        # 이후 단계
├── configs/               # 실험별 설정 (모델, k, 시드, 판별 방식)
├── scripts/
│   └── download_data.sh   # 데이터는 저장소에 넣지 않고 받는 스크립트로
├── results/               # 실험별 결과 CSV (작은 파일만)
├── notebooks/             # 탐색·분석용 Jupyter 노트북
└── figures/               # 표·그림 생성 스크립트와 결과
```

### 루트

- `README.md`: 프로젝트 목적, 설치, 실행 방법, 데이터 받는 법
- `requirements.txt`: 재현을 위해 `gliclass`, `transformers`, `torch` 버전을 고정

### `labels/` — 공격 라벨

- `attack_labels_v19.csv`: 공격 기법 라벨 목록 (v19 기준)
- `stratus_mapping.csv`: Stratus Red Team 기법과 라벨 간 매핑
- `build_labels.py`: 위 CSV 파일을 생성·갱신하는 스크립트
- raw 데이터 라벨 구분 계획은 [`labels/README.md`](labels/README.md) 참고

### `src/` — 파이프라인 코드

| 파일 | 역할 |
|---|---|
| `preprocess.py` | 서비스 이벤트 제외, 라벨 누출 정보 제거, 반복 이벤트 압축 |
| `windows.py` | 세션 분할, 슬라이딩 윈도우 생성 |
| `features.py` | 행위 특징과 파생 특징을 분류 모델 입력 텍스트로 변환 |
| `hier_classify.py` | 계층 분류 (top-down / bottom-up) |
| `evaluate.py` | 분류 결과 평가 |
| `finetune.py` | 모델 파인튜닝 (이후 단계) |

### `configs/` — 실험 설정

실험별 설정 파일을 둡니다. 모델, k, 시드, 판별 방식 등을 설정 파일로 관리합니다.

### `scripts/` — 보조 스크립트

- `download_data.sh`: 데이터 다운로드 스크립트. 원본 데이터는 저장소에 넣지 않고 이 스크립트로 받습니다.

### `results/` — 실험 결과

실험별 결과 CSV를 저장합니다. 용량이 작은 파일만 커밋합니다.

### `notebooks/` — 노트북

데이터 탐색, 중간 결과 확인, 오류 분석 등 대화형 작업용 Jupyter 노트북을 둡니다. 재사용할 로직은 `src/`로 옮기고, 노트북에서는 `src`를 import해서 씁니다.

### `figures/` — 표·그림

논문·보고서용 표와 그림을 만드는 스크립트와 그 결과물을 둡니다.
